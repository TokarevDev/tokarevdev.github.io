01 · Architecture, lifecycle & validation

Last Seed Survivor

An architecture-first Unity 6 mobile auto-shooter with engine-free domain state, explicit frame orchestration, transactional pooled lifecycles, and project-wide validation.

  • Reward generation, policy, commit, application, presentation, and guarded ad operations have separate ownership and failure behavior.
  • Segmented-worm spawning rolls back completed stages in reverse order, while combat, movement, balance, and presentation remain separate.
  • The current gate covers the project build, 299 EditMode tests, 29 PlayMode tests, configuration and serialized-reference checks, and Zenject validation for three scenes.

02 · Architecture & delivery

2D Asteroids Survival

A playable Unity survival game used to demonstrate dependency direction, scene composition, gameplay lifecycle, and asynchronous navigation.

  • Zenject composition roots connect Core contracts, Infrastructure, Gameplay, and UI without runtime service lookup.
  • SignalBus subscriptions and UniTask scene transitions have explicit initialization, teardown, and duplicate-action guards.

Engineering approach & core stack

Engineering approach

Architecture makes ownership, order, and failure visible.

I use plain C# for deterministic rules and state, Unity components for engine integration, composition roots for dependencies, and named lifecycle stages where partial failure requires rollback.

Architecture

Explicit dependencies

Constructor injection where practical, Zenject at composition boundaries, interfaces for replaceable infrastructure, and Assembly Definitions for dependency direction.

Gameplay

Data and runtime state

ScriptableObjects hold authored configuration while dedicated runtime models own mutable combat and progression state.

Lifecycle

Failure-safe ownership

Subscriptions, async operations, pooled entities, and scene state have explicit owners, reverse-order rollback, cancellation, and best-effort cleanup.

Validation

Repeatable evidence

EditMode and PlayMode tests, scene dependency checks, serialized-reference validation, deterministic simulations, and profiler markers turn architectural intent into verifiable behavior.
