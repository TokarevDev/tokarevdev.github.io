Key engineering decisions

Order, ownership, and platform boundaries stay visible in code.

One named fixed-step pipeline

GameplayFixedLoop is the only IFixedTickable entry point. It runs player state, movement, integration, projectiles, world bounds, collisions, and presentation synchronization in an explicit order.

Custom physics and toroidal space

Plain C# bodies, integrators, circle and segment queries, elastic response, and ToroidalWorld2D own gameplay simulation without Physics2D or dynamic Rigidbody2D behavior.

Validated data boundaries

Player, enemy, and world balance load from JSON. Validation rejects invalid values and missing, unknown, null, duplicate, or incorrectly cased enemy keys before gameplay scenes open.

Transactional pooled lifecycle

ObjectPool<T> tracks created instances, provides FIFO reuse, and rejects duplicate returns. EnemyPool centralizes rent, initialization, registration, activation, teardown, and rollback while concrete pools keep type-specific work.

One input snapshot, two strategies

Desktop and mobile strategies use Unity's classic Input API behind one contract. PlayerInputStateProvider samples the selected strategy once per rendered frame for movement and both weapons.

Guarded platform integration

UniTask navigation prevents duplicate transitions and restores UI after failure. Firebase Analytics and AdMob stay behind adapters; missing ad configuration selects a disabled service instead of breaking bootstrap.

Runtime and maintainability

Hot paths and failure paths are explicit.

Gameplay avoids scene-wide lookup, repeated component discovery, and temporary hot-loop collections. Cached references, registries, and owned lifecycle operations keep cost and cleanup predictable.

Centralized collision and lookup

Enemy and projectile registries support custom circle and segment queries; HashSet membership and direct entity mappings prevent duplicate registration and concrete-pool scans.

Failure-safe spawn lifecycle

Enemy and projectile spawn paths reverse completed registrations and return rented views if a later stage fails. SignalBus and event subscriptions have deterministic teardown.

Authored data in the right format

JSON owns extensible runtime balance; ScriptableObjects remain where Unity asset references are appropriate. Unity-facing dependencies are serialized, validated, and cached before gameplay.

Review and delivery

Feature-complete code with playable desktop and mobile builds.

The public repository contains the complete Unity project, configuration, setup notes, and architecture review map. The 21-point architecture review is closed; final Android device and release-build validation remains a separate gate.
