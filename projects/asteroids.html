2D Asteroids Survival

A complete playable survival game designed as a compact production system: custom deterministic-style simulation, explicit dependency direction, transactional pooling, validated balance data, lifecycle-safe platform services, and separate desktop/mobile input.

Architecture intent

Keep simulation, orchestration, views, and platform code independently replaceable.

The gameplay loop stays simple to play, but its boundaries are intentionally explicit. High-level systems depend on stable contracts; Unity views and platform adapters remain at the edge.

Key engineering decisions

The codebase makes its operating model visible.

Named fixed-step loop

One GameplayFixedLoop coordinates input, simulation, collision resolution, cleanup, and view synchronization in an explicit sequence instead of relying on magic execution-order numbers.

Single input snapshot

Physical controls are polled once per frame and distributed as immutable state. Desktop and mobile strategies change at the platform boundary without branching throughout gameplay.

Transactional pooled lifecycle

The shared flow is rent → initialize → bind → activate. Partial registration failures roll back in reverse order and return ownership to the pool before propagating the error.

Identity registries

Dictionary-backed maps connect logical entities, views, damage contracts, and lifecycle owners. Consumers do not scan subtype pools or use repeated List.Contains membership checks.

Validated configuration

JSON is converted into stable keys and typed runtime parameters at the loading boundary. Nulls, duplicates, unknown keys, and missing required entries fail before the game loop starts.

Optional integrations stay optional

Firebase Analytics and AdMob sit behind explicit adapters. Missing optional configuration uses a diagnosed disabled path instead of breaking core bootstrap.

Runtime and memory

Frequent work is bounded, cached, and owned.

The hot path avoids runtime scene searches, repeated GetComponent calls, LINQ queries, temporary collections, and per-frame string work.

Pooled entities

Asteroids, fragments, UFOs, projectiles, logical models, and collision VFX are reused. Reset and unregister paths are centralized before pool return.

Custom physics boundary

Fixed-step integration, circle and segment tests, elastic response, toroidal coordinates, and view synchronization live outside MonoBehaviour orchestration.

Lifecycle-safe async flow

UniTask scene transitions prevent duplicate actions, expose failures, and keep navigation ownership separate from menu and game-over views.

Delivery evidence

The architecture is executable, not theoretical.

The public repository includes code maps and build instructions. Gameplay can be reviewed through source, video, Windows build, or Android APK.

Gameplay scope

Acceleration, inertia, world wrap, bullets, rechargeable multi-target laser, fragmentation, UFO pursuit, score, lives, and responsive HUD.
